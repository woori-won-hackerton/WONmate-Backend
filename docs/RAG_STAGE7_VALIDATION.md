# 7단계 검증 기록 (2026-10-27)

이 문서는 7단계 전체 데이터 감사부터 모델 호출 전환, 기능 제거, CLI 적재 정리까지의 누적 변경과 검증 결과를 기록한다. 전체 PDF 감사 당시 수치와 현재 코드의 회귀 테스트 결과를 구분한다.

## 현재까지 반영한 변경

| 영역 | 최종 변경 내용 |
|---|---|
| 데이터 감사 | `FullDataAuditTests`로 문서 등록·상품 매핑·파일 해시·벡터·청크 번호·전체 물리 페이지 본문을 대조하고 `PdfEvidenceReviewTests`로 원본 근거 페이지를 렌더링 |
| 매핑 안정성 | 명시된 상품 ID와 제공된 상품명이 불일치하면 매핑 거부. API·DB 실패, 손상 PDF, 혼합 배치 실패 시 정상 문서 보존 검증 |

현재 공개 질문 유형은 `TERM_EXPLANATION`, `INSURANCE_CONCEPT`, `PRODUCT_EXPLANATION`이다. `PRODUCT_EXPLANATION`에만 단일 양수 `productId`를 지정한다. `POST /api/rag/search`, `POST /api/rag/ask`, local 프로필의 `GET /api/documents`를 유지한다. `POST /api/admin/documents/ingest`는 제거했다.

`documents/`에 파일을 추가하거나 서버를 시작하는 것만으로 임베딩하지 않는다. 프로젝트 루트에서 아래 명령을 명시적으로 실행하면 메타데이터에 등록된 PDF를 임베딩하고 청크를 DB에 저장한다. 같은 해시·모델의 완료 문서는 건너뛰며 실패 후 같은 명령으로 재시도할 수 있다.

```powershell
.\gradlew.bat ragIngest
```

원문·메타데이터·`.env`는 Git 제외 대상이므로 다른 컴퓨터에 별도 준비한다. 새 DB의 상품 ID가 다를 수 있어 `productId:null` 기반 상품명 매핑 또는 대상 DB의 정확한 ID를 사용한다. 자세한 절차는 [documents 적재 가이드](RAG_LOCAL_LOAD_GUIDE.md), 모델 설정은 [Spring AI 전환 문서](RAG_SPRING_AI.md), 현재 요청 계약은 [API 예시](RAG_API_EXAMPLES.md)를 따른다.

## 최신 회귀 테스트 결과

마지막 코드 변경 후 로컬 PostgreSQL 연결 환경변수를 설정하고 `gradlew.bat test --offline`을 실행했다. **총 45개 중 38개 통과, 7개 skip, 실패 0개, BUILD SUCCESSFUL (37초)**다. 이번 문서 정리에서는 코드를 변경하거나 테스트를 다시 실행하지 않았다.

| 검증 | 결과 |
|---|---|
| Spring AI 모델 설정 | 지정 모델명, 임베딩 차원, 타임아웃, SDK 중첩 재시도 방지, strict schema와 store:false 확인 |
| 모델 호출 | 로컬 HTTP 서버로 Spring AI → SDK 전송 경로와 구조화 응답·거절·잘못된 응답·401/500 처리 확인 |
| 임베딩 | 배치·응답 순서·재시도·타임아웃·잘못된 벡터 거부 확인 |
| 질문 API | 남은 3개 유형 유지, 제거된 비교·추천 유형의 HTTP 400 확인 |
| 문서 API | 제거된 적재 경로의 HTTP 404 및 서비스 미호출, 문서 목록 조회 유지 확인 |
| 일괄 적재 | 실제 PostgreSQL과 모의 임베딩으로 동일 문서 skip, 변경 문서 교체, API·저장 실패 롤백, 손상 PDF 혼합 배치 보존 확인 |

7개 skip은 전체 PDF 감사 1개, 원본 렌더링 1개, 수동 청크 품질 검토 1개, 실제 임베딩 1개, 실제 검색 1개, 실제 질문 2개다. 전체 PDF 감사는 아래의 앞선 실행에서 통과했으며 모델 전환·CLI 정리 후 다시 실행하지 않았다. 최신 회귀 테스트에서 실제 OpenAI 유료 호출이나 PDF 재임베딩·재적재는 수행하지 않았다. 다른 컴퓨터에서의 초기화 가이드 실행도 미검증이다.

## 전체 PDF 감사 당시 실행한 검증

현재 원본은 상품 폴더 10개, 메타데이터 10개, PDF 20개(TERMS/SUMMARY 각 10개)다. 과거 build 산출물은 현재 실행의 성공 증거로 사용하지 않았다.

실제 `.env`의 로컬 DB 연결 설정으로 `test --offline --rerun-tasks`를 실행했다. 총 41개 중 36개 실행 성공, 5개 opt-in 테스트 skip이었다. PostgreSQL 저장·조회·벡터 순위·상품 필터·문서 교체/롤백 테스트가 포함된다. API 오류 테스트는 외부 OpenAI 대신 로컬 HTTP 서버를 사용했다. 이후 추가한 상품명 불일치 및 손상 PDF 혼합 배치 회귀 테스트와 원본 렌더링 테스트도 별도 실행에 성공했다.

전체 PDF 감사 단일 실행: `RAG_DATA_AUDIT=true`, `RAG_PDF_REVIEW=true`와 DB 연결 환경변수를 설정하여 `gradlew.bat test --offline` 실행. **당시 43개 중 38개 통과, 5개 skip, 실패 0개, BUILD SUCCESSFUL (8분 43초)**. 전체 감사도 이 실행에서 통과했다. 실행하지 않은 5개는 수동 청크 품질 검토 1, 실제 임베딩 1, 실제 검색 1, 실제 질문 2다. 이후 77쪽 렌더링을 추가한 `PdfEvidenceReviewTests`도 별도 실행 성공했다(16초). build의 HTML/XML 보고서는 후속 테스트 실행으로 갱신되므로 당시 집계는 이 기록을 참고한다.

| 항목 | 검증 범위 / 결과 |
|---|---|
| 임베딩 API | 배치, 429/5xx 재시도, 응답 index 복원, 차원 오류, 401 즉시 실패, 타임아웃 통과 |

## 수정한 문제

전체 읽기 전용 감사 산출물: **20문서, 13,934 PDF 페이지, 19,306 청크, 무결성 오류 0건**. [문서별 감사 데이터](RAG_STAGE7_DATA_AUDIT.json)를 함께 보관한다. 20개 로컬 등록 문서와 DB 문서 수가 일치하며, 페이지·본문 대조 오류도 0건이다. 동일 문서 내 반복 본문은 355개 그룹이다. 이는 중복 적재나 중복 API 호출을 의미하지 않으며 특약 공통 문구와 페이지 문구 반복을 포함한다. 이미지 전용 OCR 후보는 17쪽이다. 앞선 감사 실행의 테스트 보고서는 동시 Gradle 실행의 파일 충돌로 실패했으나 최종 단일 실행은 성공했다.

OCR 후보: product_01 2·319·320쪽, product_04 367·368쪽, product_05 2026·2027쪽, product_06 617·618쪽, product_07 554·555쪽, product_08 454·455쪽, product_09 1494·1495쪽, product_10 6373·6374쪽. 실제 PDF 페이지 수와 PDF 뷰어의 인쇄/내부 페이지 표시가 다를 수 있다. 렌더링의 하단 표시 대신 PDFBox의 물리 인덱스를 사용했다.

`DocumentIngestionRepository.resolveProduct`는 명시된 ID가 존재하면 다른 상품명을 함께 제시해도 허용했다. 이제 이름이 제공되면 DB 상품명과 정확히 일치해야 한다. 명시 ID만 제공하는 기존 계약은 유지한다. 회귀 테스트는 다른 상품명 거부와 ID만 제공하는 경우를 모두 검증한다.

`FullDataAuditTests`를 추가했다. 외부 호출 없이 전체 메타데이터와 원본을 탐색하여 DB 등록 수, 상품명/명시 ID, 유형, 완료 상태, SHA-256, 청크 번호 연속성, 1536차원 비영 벡터, 전체 청크의 물리 페이지 범위와 공백 정규화 본문 포함 여부를 대조한다. 동일 문서 내 동일 본문 그룹과 OCR 필요 페이지도 보고한다. 동일 본문 반복은 출처와 문맥이 다를 수 있어 자동 삭제하지 않는다. 페이지 검사 결과는 표의 의미적 행·열 관계까지 보증하지 않는다.

## 검색 개선 판단

현재 질문 파이프라인은 상품별 SUMMARY, 지급조건 TERMS, 제한조건 TERMS를 독립 검색한다. 상품 설명은 지정된 단일 상품만 검색하고, 용어·개념 설명은 요약서 점수로 최대 5개 상품에서 근거를 찾는다. 같은 청크 ID는 통합 컨텍스트에서 중복 제거한다. 실제 임베딩 기반 오류와 전후 수치를 확보하지 못했으므로 비중 조정·본문 중복 제거·Hybrid Search를 임의 추가하지 않았다.

## 미완료 / 알려진 한계

실제 OpenAI 질문·검색 결과 평가, 모든 상품의 금액/조건 표 육안 검토, DB 연결 단절, 다중 프로세스 대량 적재 경쟁은 미완료다. OCR과 표 구조 복원, 청킹 버전 변경에 따른 자동 재적재, 문장별 의미적 인용 검증은 미구현이다. 출처 ID가 유효하다는 사실만으로 답변의 보험 의미가 정확하다고 판단하지 않는다.
